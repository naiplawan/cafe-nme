# Draft release notes: Cafe'nMe 0.2.0

## Highlights

- New accounts verify their email address before they can sign in or create a shop.
- Device pairing and webhook request handling have stronger protections against automated abuse and oversized requests.

## Fixes and improvements

- Login and signup throttling no longer lets failed attempts against one email block its owner.
- POS pairing codes are eight digits, and request limits use the trusted client address.
- LINE webhook bodies are limited to 1 MiB and read incrementally.

## Upgrade

- Apply backend migration `0016_restore_email_verification` through the API pre-deploy step.
- Configure `RESEND_API_KEY`, `EMAIL_FROM`, and the public frontend origin as `APP_BASE_URL` on the API service.
- Ensure production frontend ingress overwrites `x-real-ip`; signup, login, and pairing fail closed if it is missing or invalid.
- Existing accounts remain verified. Password recovery remains operator-managed.

## Version recommendation

Recommend **0.2.0**. The repository's changelog defines pre-1.0 minor releases for features and patch releases for fixes; email verification is a new user-facing capability with required deployment configuration.
